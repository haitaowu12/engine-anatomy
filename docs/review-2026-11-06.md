# Content, navigation and reading review — 6 November 2026

## Scope

This revision reviews the active component entries, architecture descriptions, learning paths, experiments, model notes, H175 mechanism entries and three material-engine studies. The entry-level ledger is in [the content review](content-review-2026-11-06.md). Historical release and audit records remain historical records.

The editorial standard is to explain the part’s function, physical mechanism and connections before discussing the example’s scope. Technical terms are introduced in context. Repeated statements about what the model does not simulate have been consolidated into model notes or replaced with the relevant positive explanation.

## Technical corrections

- The turbofan momentum balance now uses incoming **air** mass and outgoing **air plus fuel** mass. It no longer subtracts inlet momentum for fuel carried by the aircraft. The same correction is present in the main plant and all three bundled studies. The source is [NASA Glenn’s gas-turbine thrust equation](https://www.grc.nasa.gov/www/k-12/airplane/turbth.html).
- The named PT6A-100 hardware study identifies its hydromechanical fuel control separately from the generic electronic torque-control experiment. The CFM56-5C study identifies its mixed exhaust separately from the teaching calculation’s separate-stream nozzle estimate. Hardware sources and bundle parity checks are recorded in the content review.
- Generic aircraft drawings now use generic installation titles. The named H175, Dash 8-300 and A340-300 identities are reserved for their corresponding realistic aircraft views. The main engine explorer is described as a separate teaching model.
- The beginner gas-path walkthrough defines intake, compression, continuous combustion, turbine work and useful output. The turbofan path also follows the bypass stream. Output steps select the aircraft view for the rotor or propeller; engine stages select the engine assembly.

## Navigation and accessibility changes

Selecting a component from the search, component groups, hierarchy or model switches to its component explanation. Experiment-stage links retain the experiment context. Starting the introductory walkthrough reassembles an opened inspection. Conceptual starting and shutdown lessons pause the running model and restore the previous pause choice when the reader leaves them.

Activity choices precede the model at all widths. On narrow screens, walkthrough text precedes the model, and experiment controls appear above it only while the experiment is selected. Search supports Enter, arrow keys, Home, End and Escape, with an announced match count. A WebGL context loss now requests the existing schematic fallback.

Reading text uses 16 px type with a 1.65 line height in the main explanation surfaces. Secondary text remains distinct at 14 px. Controls and small-screen navigation use 44 px minimum targets where updated, and search/select fields use 16 px text. Focus indicators, reduced-motion settings, semantic controls, static explanations and the schematic fallback are retained. Canonical and cross-project links now point to the primary Firebase sites.

These changes address specific readability, keyboard and reflow concerns; they are not a claim of a complete WCAG conformance audit. Relevant references are [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and [WAI’s reflow explanation](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html).

## Published layout and renderer fallback follow-up

The published application was checked at 320, 375 and 768 CSS px in Chrome. At the narrow widths, the document stayed within its viewport, the introductory lesson appeared before the model, experiment controls appeared before the canvas, and leaving the experiment hid those controls. At 375 px the H175 motor control changed to its running state and the rotor-head selection displayed its mechanism title without page overflow.

The material study exposed a separate failure path: WebGL initialization could fail and leave only a raw error above an empty 3D area. All three self-contained studies now provide a readable explanation and a link to their matching illustrated gas-path lesson when initialization fails. The link explicitly selects the existing schematic renderer. A no-JavaScript state also retains the basic explanation. The study-build wrapper reapplies this fallback after regeneration. Tests execute the embedded fallback handler and verify the architecture, renderer and lesson destinations in all three pages. The bundled thermodynamic calculations still match the source across the existing 72 cases.

The final Engine Anatomy 5.1.1 local gate passes all 122 tests. The release check verifies six pages, 88 local dependency references, documentation parity and unique controls. Published browser interaction also confirmed that keyboard search opens the matching component, Back restores the prior component and diagram lens, and the 2D control diagram fits the narrow viewport.
